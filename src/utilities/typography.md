# Типографика через Typopo

Все языковые правила выполняет `typopo` (версия зафиксирована в `package.json`). Собственных списков коротких слов и ограничений длины неразрывных цепочек нет. Библиотека исправляет пробелы, кавычки, тире, многоточия и другие типографические символы по своим правилам.

Локали сайта сопоставлены в `src/utilities/typography.ts`: `cs` → `cs`, `en` → `en-us`. `removeLines: false` сохраняет пустые строки. Небольшая обёртка сохраняет пробелы по краям фрагмента для безопасного соединения с соседними inline-элементами.

## Обычные строки

```tsx
import { applyTypography } from "@/utilities/typography";

<h2>{applyTypography(heading, { locale })}</h2>
<p>{applyTypography(description, { locale })}</p>
```

Передавайте локаль страницы явно; запасное значение — `cs`. Выводите результат как обычный текст React, без HTML-конвертации. Для технических значений, которые должны остаться дословными, не вызывайте обработку либо передавайте `{ enabled: false }`.

`SectionHeading`, `HighlightedText`, `Eyebrow`, `CMSLink` и `RichText` принимают `locale` и `typography={false}`. Локаль проходит через `RenderBlocks` и вложенные Rich Text-блоки. Общие клиентские контролы (`Button`, `Label`, поля выбора, сообщения формы) получают локаль через `LocaleProvider`, установленный в оболочке сайта. Отдельно отображаемые контролы вне сайта можно обернуть в этот provider.

`typographyChildren` обрабатывает непосредственные текстовые дочерние элементы. Он не выполняет и не клонирует вложенные React-компоненты: текст внутри собственного компонента обрабатывается в месте его вывода.

## Rich Text и выделения

```tsx
<RichText data={content} locale={locale} />
<RichText data={content} locale={locale} typography={false} />
```

`applyRichTextTypography` обрабатывает копию Lexical-дерева. Текстовые участки собираются внутри абзацев, заголовков, цитат и элементов списка, включая текст ссылок. Код, явные переносы и неизвестные inline-расширения служат границами обработки. Новые типы inline-узлов следует явно подключать в адаптере.

Typopo может менять длину текста (`...` → `…`), поэтому `typographySegments.ts` использует библиотеку `diff` для сопоставления исправленных символов с исходными узлами. Сопоставление учитывает эквивалентные формы пробелов, кавычек и регистра; оно только сохраняет границы оформления и не создаёт типографических исправлений. Замена нескольких символов одним наследует оформление первого заменённого символа. Этот же адаптер сохраняет выделенные фрагменты в `HighlightedText`.

Адреса ссылок и другие метаданные узлов не обрабатываются. Видимый текст ссылки обрабатывается как текст. Исходные CMS-данные и значения полей формы не меняются. Настройка отключения внешнего RichText не распространяется на содержимое пользовательских блоков автоматически — их компоненты управляют своим выводом.

## Проверки

`src/utilities/typography.int.spec.tsx` проверяет чешские и английские правила, замену символов с изменением длины, ссылки и выделения, передачу локали через блоки и клиентские контролы, сохранность CMS-данных и одинаковый HTML на сервере и клиенте.

После обновления Typopo проверьте эти тесты и отображение длинных текстов на мобильной ширине: набор исправлений определяется библиотекой.

Документация: [Typopo](https://github.com/surfinzap/typopo), [jsdiff](https://github.com/kpdecker/jsdiff).
